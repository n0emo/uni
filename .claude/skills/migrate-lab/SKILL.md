# Migrating a single lab

Migrate **one lab at a time**. A lab is done when its report compiles to PDF via `mise run
report <num>` and (if it has code) its sources build via the course's build task.

Compare `bachelors/term-2/*` (legacy) against `bachelors/term-1/entrance-to-c` (fully
migrated) whenever something here is ambiguous — term-1 is the reference implementation.

## Target layout

```
bachelors/term-N/<course-kebab-case>/
├── mise.toml          # course-level tasks (create on the first lab of the course)
├── common.typ         # shared pgups report preamble (likewise)
├── .gitignore         # build/, reports/, plus language-specific outputs
├── CMakeLists.txt     # only for CMake courses: add_subdirectory(lab-N) per lab
└── lab-N/
    ├── report.typ     # the Typst report
    ├── assets/        # figures referenced by report.typ
    ├── src/           # program sources
    ├── CMakeLists.txt # or Cargo.toml / pyproject.toml / pom.xml / project.clj
    └── ЛР N.docx      # the ORIGINAL report — keep it, never delete
```

Rules that are not negotiable:

- Directories are kebab-case: `Lab 1` → `lab-1`, `lab_1_1` → `lab-1-1`, `c_lab_1` → `src`.
- Move with `git mv`, never `rm` + `cp` — history matters more than tidiness here.
- The original `.docx`/`.odt`/`.pdf` handed in at the time stays in the lab directory as the
  source of truth. They are Git LFS-tracked already (`.gitattributes` at the repo root).
- `Шаблон отчёта.docx`/`.odt` at the course root is the department's template, not a report.
  Leave it where it is; do not convert it.
- Generated PDFs go to a gitignored `reports/` at the course root, never next to the source.

## Procedure

### 1. Survey the lab

```bash
ls -R bachelors/term-N/<course>/<lab-dir>
```

Identify, before touching anything:

- the report document (`ЛР<N>.docx`, `ЛР<N>.odt`, sometimes `Report.docx`);
- task statements (`Задание <N>.docx`, `Варианты*.docx`) — these are reference material, keep
  them as-is, do not convert;
- the sources and which language/toolchain they belong to;
- any existing `justfile`, `*.sln`, `*.vcxproj`, `Makefile` that used to build it.

If the toolchain is dead or Windows-only (WinAsm `.wap`, old `.sln` for .NET Framework,
MathCAD, Delphi), **migrate only the report** and leave sources untouched as an archive. Do
not invent a build for something that cannot be built. Say so in the final report to the user.

### 2. Restructure directories

```bash
cd bachelors/term-N/<course>
git mv "Lab 1" lab-1
git mv lab-1/c_lab_1 lab-1/src
git mv lab-1/ЛР1.docx "lab-1/ЛР1.docx"   # only if the name needs normalizing
```

Keep source file names as they were. Only the directory names get normalized.

### 3. Convert the report with pandoc

```bash
pandoc "lab-1/ЛР1.docx" -t typst --extract-media=lab-1/assets -o lab-1/report.typ
```

`.odt` is read natively by pandoc — no pre-conversion. A legacy `.doc` needs
`soffice --headless --convert-to docx` first.

pandoc puts images in `lab-1/assets/media/`; flatten it:

```bash
git mv lab-1/assets/media/* lab-1/assets/ && rmdir lab-1/assets/media
```

Word equations and drawings come out as `.wmf`/`.emf`, which Typst cannot read. Convert them:

```bash
soffice --headless --convert-to png --outdir lab-1/assets lab-1/assets/image1.wmf
rm lab-1/assets/image1.wmf
```

Prefer retyping a `.wmf` **formula** as real Typst math over embedding its raster — the
formula is usually already in the task statement.

Commit the raw pandoc output first, before cleaning it up. That keeps the "what pandoc did"
and "what I rewrote" diffs separable (`a231c32` is the precedent).

### 4. Rewrite it onto `@local/pgups`

Full catalogue of pandoc artefacts and their fixes: `references/pandoc-cleanup.md`. The shape
to reach:

```typ
#import "../common.typ": *

#show: report.with(number: "1", title: "Создание консольного приложения")

= Задание
...
== Исходный текст программы

#code-file(read("./src/main.c"), name: "main.c")
```

The three things that always have to happen:

- **Delete the front matter and the grading sheet.** Everything pandoc emitted from the title
  page (ФЕДЕРАЛЬНОЕ АГЕНСТВО…, the Выполнил/Проверил table, Санкт-Петербург, the
  `Оценочный лист результатов` table, the Доцент кафедры signature block) is generated by
  `lab-report` from `common.typ`. It must not survive in `report.typ`.
- **`#strong[...]` paragraphs become headings.** Word reports fake headings with bold text;
  pandoc faithfully reproduces the fake. `#strong[Цели работы:]` → `= Цель работы`. Nest with
  `==`/`===` to match the report's real structure.
- **Listings become `#code-file(read(...))`.** Never paste program text into the report — read
  it from `src/` so the listing and the code that is built cannot drift apart.

If `common.typ` does not exist yet, create it from term-1's (`bachelors/term-1/entrance-to-c/common.typ`),
filling `faculty`, `department`, `discipline`, `year`, `student`, `teacher` and `variant` from
the title page pandoc just produced — read them off it before deleting it.

Then format:

```bash
typstyle --inplace --line-width 100 --wrap-text lab-1/report.typ
```

### 5. Give the code a real build tool

One build tool per language, declared in the course `mise.toml` `[tools]` so it is pinned:
CMake for C/C++, Cargo for Rust, uv for Python, Maven for Java, Leiningen for Clojure. Exact
`[tools]` entries, config file skeletons and task definitions per language:
`references/build-tools.md`.

Delete the legacy `justfile` once its recipes are covered by mise tasks.

### 6. Wire up mise

Course `mise.toml` — the `report`/`report-all` pair is identical in every course, copy it and
adjust the range:

```toml
[tasks."ensure-reports-dir"]
extends = "mkdir"

[tasks.report]
description = "Compile one lab's report to PDF"
usage = 'arg "<num>" help="lab number (1-7)"'
depends = [{ task = "ensure-reports-dir", args = ["reports"] }]
run = 'typst compile --root . "lab-{{ usage.num }}/report.typ" "reports/lab-{{ usage.num }}.pdf"'

[tasks."report-all"]
description = "Compile every lab's report"
depends = [
  { task = "report", args = ["1"] },
  { task = "report", args = ["2"] },
]
```

Extend `report-all` with the new lab's number. Prefer `extends` on a root task template
(`mkdir`, `cmake:configure`, `cmake:build`, `typst:compile`) over repeating raw invocations;
declare `sources`/`outputs` on build tasks so mise can skip them.

Register the course in the root `mise.toml` — once per course, alphabetically, `./`-prefixed
with a trailing slash:

```toml
[monorepo]
config_roots = [
  "./bachelors/term-2/programming-c/",
]
```

A course `.gitignore` with at least `build/` and `reports/` (plus `target/`, `.venv/`, `out/`
as the language requires).

### 7. Verify

Run from inside the course directory, not the repo root:

```bash
cd bachelors/term-N/<course>
mise tasks          # the new tasks are listed
mise run report 1   # exits 0, reports/lab-1.pdf appears
mise run build      # if the lab has code
```

Open the PDF and check it against the original `.docx` — same sections, figures present,
formulas not mangled. Report honestly if something did not survive the conversion.

### 8. Commit

One commit per lab, subject prefixed with the course directory name, imperative, lowercase
after the prefix:

```
programming-c: migrate lab 1 to Typst and CMake

Converted from the "ЛР1.docx" handed in at the time; the docx stays
alongside it as the original.
```

## Checklist

- [ ] Directories kebab-case, moved with `git mv`
- [ ] Original `.docx`/`.odt` still present
- [ ] `report.typ` imports `../common.typ`, no leftover title page or grading sheet
- [ ] No `#strong[...]` standing in for a heading
- [ ] Listings read from `src/`, not pasted
- [ ] `.wmf`/`.emf` gone; figures render
- [ ] `typstyle --line-width 100` clean
- [ ] Build tool config present; legacy `justfile` deleted
- [ ] Course `mise.toml` has the lab in `report-all`; course in root `config_roots`
- [ ] `mise run report <n>` and `mise run build` both succeed
